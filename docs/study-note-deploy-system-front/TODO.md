## 2026-09-14 접기/펼치기 - ASCII 도식 코드블록을 접힌 상태로

- 배경: ASCII 도식은 LLM 검색(청킹, 하이브리드 검색) 입력으로는 필요하지만 사람이 읽을 때는 길다. 접힌 블록으로 두고 필요할 때 펼치고 싶다.
- 현재: 프론트가 raw HTML을 버려 `<details>`가 렌더링되지 않는다(GitHub에서만 접힘).
- 선택지: (1) rehype-raw 추가 + sanitize(details/summary만 허용) (2) remark-directive로 `:::details 제목` 문법 지원(raw HTML 금지 유지, 권장) (3) 코드블록 fence 정보 문자열(예: ```text fold)을 보고 접는 커스텀 code 렌더러(문서 수정 최소).
- 결정 필요: 접힌 블록의 텍스트도 색인 대상인지(색인은 md 원문 기준이라 영향 없음 - 확인).

## 2026-09-21 demo 블록 렌더링 - CSS·애니메이션 주제를 화면에서 보이게

- 배경: study-note 에 언어별 문법·API 주제를 만드는 중이다(13개 언어·약 700주제 예정, 1단계 리스트업은 11개 언어 610주제 완료). 그중 **CSS·애니메이션·HTML 렌더링 주제는 코드만 읽어서는 이해가 안 된다** - 호버 전환, 키프레임, 그리드 자동 배치 같은 것은 움직이는 걸 봐야 안다. 그래서 study-note 쪽에 형식을 먼저 정해 두었다: `reference/render-rules.md`(study-note 커밋 `81dd0dc`).
- 형식: 코드펜스 언어 뒤에 **`demo`** 한 단어를 붙이고(```` ```html demo ````), 블록 바로 아래에 `> **보이는 것** - ...` 줄을 의무로 단다. `> **바꿔 볼 것** - ...` 은 권장. 각 주제 리스트업 표에 `렌더` 칸(필수/도움/불필요)이 있어 **대상 주제는 이미 목록화돼 있다**(`cs/foundations/languages/<언어>/syntax/README.md`).
- 현재: 프론트가 react-markdown + remark-gfm + rehype-highlight 라 fence 정보 문자열은 code 렌더러에서 받을 수 있다. 위 「접기/펼치기」 항목의 선택지 (3)(```` ```text fold ````)과 **같은 메커니즘**이라 커스텀 code 렌더러를 한 번 만들면 둘 다 처리된다 - 함께 설계하는 게 싸다.
- 해야 할 것: (1) code 렌더러에서 info string 파싱(`html demo` / `text fold` / 조합 가능성 - 토큰 배열로 받을 것) (2) `demo` 는 **격리된 iframe(sandbox)** 안에서 실행 - 이건 보안보다 **스타일 격리** 때문이다. demo 블록의 `<style>` 이 문서에 그대로 들어가면 위키 전체 CSS 를 오염시킨다 (3) iframe 높이 자동 조절 또는 고정 높이 규약 결정 (4) 원본 코드도 함께 보여 줄지(토글) - 문법 주제라 **코드가 본문**이므로 기본 노출 쪽이 맞아 보인다.
- 지금 안 해도 되는 이유: `보이는 것` 줄이 md 에 있으므로 **렌더링이 없어도 읽는 사람이 무슨 일이 일어나는지 안다.** GitHub·에디터에서는 평범한 코드블록으로 보이고 아무것도 깨지지 않는다. 즉 study-note 쪽 작성과 이쪽 구현이 **순서에 묶이지 않는다.**
- 확인 필요: 색인 영향 없음으로 보인다(색인은 md 원문 기준이고 demo 블록은 코드블록이라 그대로 들어간다). 다만 **LLM 검색 입력에 데모 코드가 섞이는 게 도움인지 잡음인지**는 판단이 필요하다 - 위 「접기」 항목의 색인 질문과 같은 성격.
- 나중에: `바꿔 볼 것` 에 적힌 값을 조작 UI(슬라이더·토글)로 승격. 예 - `.3s` → `2s`, `ease` → `linear`.
