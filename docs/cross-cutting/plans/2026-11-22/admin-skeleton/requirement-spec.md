## 1. 목표·대상 (필수)

운영자 한 명이 `https://admin.junproject.xyz` 에 ID/PW 로 로그인해 **배포 이력 · 로그 · 서비스 상태 · 로그인 시도 기록**을 읽기 전용으로 볼 수 있게 한다.

대상 저장소: 새 `study-note-deploy-system-admin`(Next.js) · `study-note-deploy-system-observe`(로그인 시도 저장·잠금 판정 API) · `study-note-deploy-system-ci-cd`(서비스 등록) · `study-note-deploy-system-alert`(감시 대상 추가) · 엣지 nginx(새 서브도메인).

## 2. 경계·불변식 (필수)

- **읽기 전용**: 이번 어드민은 다른 서버의 상태를 바꾸지 않는다(배포 실행·알림 설정 변경 없음 — ⑥⑦). 어드민이 다른 서버에 쓰는 것은 관측 서버의 로그인 시도 기록과 알림 서버의 이벤트(잠금 발생)뿐이다.
- **비밀값은 서버 쪽에만**: `X-Deploy-Secret`·`X-Observe-Secret`·`X-Alert-Secret`·세션 서명 키·비밀번호 해시는 어드민 서버 프로세스의 환경 변수에만 있다. 브라우저로 가는 응답(HTML·JSON·스크립트 묶음)에 들어가지 않는다. 다른 서버 호출은 전부 어드민의 서버 쪽 코드에서 한다.
- **인증 경계**: 로그인 화면·로그인 요청·헬스 경로를 뺀 **모든 화면과 데이터 경로**는 유효한 세션이 없으면 내용을 주지 않는다(화면은 로그인으로 보내고 데이터 경로는 401). 화면마다 따로 검사를 붙이는 방식이 아니라 한 곳(공통 진입)에서 막고, 새 경로를 더했을 때 기본이 "막힘"이어야 한다.
- **계정**: 1개. ID 와 비밀번호 **해시**(argon2id — 검증된 라이브러리)를 환경 변수로 받는다. 평문 비밀번호는 어디에도 저장하지 않는다. 설정이 비어 있으면 모든 로그인을 거절한다(빈 값이 통과가 되지 않는다). ID 가 틀려도 비밀번호가 틀려도 응답과 걸리는 시간이 구별되지 않는다.
- **세션**: 서명한 쿠키(`HttpOnly`·`Secure`·`SameSite=Strict`·경로 `/`), 발급 뒤 **12시간**이 지나면 무효(연장 없음). 로그아웃은 쿠키를 지운다. 서명이 맞지 않거나 만료된 쿠키는 세션 없음과 같다. 상태를 바꾸는 요청(로그인·로그아웃)은 같은 출처에서 온 것만 받는다(`Origin` 검사).
  - 알려진 한계(수용): 쿠키만으로 세션을 판정하므로 로그아웃 전에 복사된 쿠키는 만료까지 유효하다. 전체 무효화 = 서명 키 교체.
- **잠금(관측 서버가 판정 — 어드민 두 자리가 같은 답을 본다)**: 계정 기준 **연속 5회 실패 → 15분 잠금**. 잠금 중에는 맞는 비밀번호도 거절하고, 그 시도도 기록한다. 성공하면 실패 횟수는 0. 잠금이 걸리는 순간 알림 서버로 이벤트 1건(`POST /events`).
- **속도 제한**: 같은 IP 에서 로그인 요청이 **분당 10회**를 넘으면 429(비밀번호 검증을 하지 않는다). 어드민 인스턴스 메모리에서 센다(자리 전환·재시작 때 0 이 된다 — 수용). 클라이언트 IP 는 엣지가 붙이는 헤더에서만 읽는다.
- **시도 기록**: 모든 로그인 시도(성공 · 실패 · 잠금 중 거절 · 속도 제한)를 시각 · 결과 · IP · User-Agent(앞 200자)로 관측 서버에 남긴다. **입력한 비밀번호와 ID 원문은 기록하지 않는다**(ID 는 "맞음/틀림"만). 보관 90일.
- **관측 서버 장애 시(임시 제한)**: 잠금 상태를 물을 수 없으면 로그인을 막지 않고, 어드민 인스턴스 메모리의 더 엄한 제한(**3회 실패 → 15분 잠금**)으로 판정한다. 그동안의 시도는 앱 로그에 남기고 메모리 대기열(상한 500)에 두었다가 관측 서버가 돌아오면 보낸다 — 대기열이 넘치거나 재시작으로 잃은 건수는 앱 로그에 남는다(조용히 버리지 않는다). 화면에는 "관측 서버에 닿지 않아 임시 제한 중"을 표시한다.
- **화면(전부 로그인 뒤)**:
  - 배포 이력: master `GET /deploys` — 서비스 선택, 최신순, 상태 · 커밋 · 실패 단계 · 걸린 시간.
  - 로그 조회: observe `GET /logs` — 기간 · 서비스 · 레벨 · 요청 ID · 검색어(2자 이상), 이어 보기(`next_before` + 응답의 from·to).
  - 상태 한눈에: alert `GET /monitors`·`GET /health`, observe `GET /health`, backend `GET /api/health/dependencies`, master `GET /health`.
  - 로그인 시도 기록: 관측 서버의 새 조회 경로.
- **한 곳이 죽어도 나머지는 보인다**: 화면이 부르는 서버 하나가 응답하지 않으면(제한 시간 5초) 그 칸만 "닿지 않음"으로 표시하고 나머지는 그린다. 다른 서버의 오류 본문을 그대로 화면에 뿌리지 않는다(상태 코드와 짧은 사유만).
- **관측 서버 추가분**: 새 테이블(로그인 시도)과 경로 — 시도 기록(쓰기) · 잠금 상태 조회 · 시도 목록 조회. 전부 `X-Observe-Secret`. 스키마는 기존 방식(`CREATE … IF NOT EXISTS`)으로 더한다. 기존 `/logs`·`/logs/stats`·`/health` 의 동작과 로그 수집은 바뀌지 않는다. 90일 삭제는 기존 30일 삭제와 같은 예약 실행에 더한다.
- **배포 규약**: 어드민도 기존 blue/green 규약(자리 2개 + nginx, `deploy/active/`, `X-Deploy-Slot`, Dockerfile `test` 단계)을 따른다. 포트 18000(nginx)·18001·18002(자리, 로컬 전용). 알림 서버가 어드민을 감시 대상에 넣는다.
- **세부(11-22 설계 선검증 반영 — 위 조항의 뜻을 확정한다)**:
  - **잠금 판정은 한 번의 호출·한 트랜잭션**: 어드민은 비밀번호를 먼저 검증하고(ID 가 틀려도 고정된 더미 해시로 argon2 검증을 똑같이 한다) 그 결과를 관측 서버의 판정 경로 하나에 보낸다. 관측 서버는 기록 · 연속 실패 횟수 갱신 · 잠금 판정을 PostgreSQL 트랜잭션 한 건으로 처리하고 판정을 돌려준다("조회 뒤 기록" 두 호출로 나누지 않는다). 로그인 성공 = 자격이 맞고 판정이 허용일 때만.
  - 실패 횟수: ID 가 틀렸든 비밀번호가 틀렸든 **모든 인증 실패**가 유일 계정의 연속 실패에 든다. 잠금이 풀린 뒤에는 0 부터. 잠금 중의 시도는 횟수를 늘리지도 잠금을 연장하지도 않는다(기록만).
  - **관측 서버 계약**(전부 `X-Observe-Secret`, 봉투는 기존과 같은 `{success,data}` / `{success:false,error}`):
    - `POST /auth/attempts` 본문 `{attempt_id(UUID), at(ISO-8601), credential_ok(bool), ip, user_agent(≤200자), replayed(bool, 기본 false)}` → `{allowed(bool), outcome("success"|"failure"|"locked"), locked_until(ISO-8601|null), lock_started(bool), failures(int)}`. 같은 `attempt_id` 를 다시 보내면 새로 세지 않고 처음의 판정을 그대로 돌려준다(응답을 잃은 재시도용). `replayed:true` 는 감사 기록만 하고 잠금 계산에 넣지 않는다.
    - `POST /auth/attempts/rejected` 본문 `{attempt_id, at, reason("rate_limited"), ip, user_agent}` → 기록만(잠금 계산 없음).
    - `GET /auth/attempts?from=&to=&before=&limit=`(1~200, 기본 50, 기간 최대 90일) → `{attempts:[{id,at,outcome,ip,user_agent,replayed}], next_before}` · `GET /auth/lock` → `{locked(bool), locked_until, failures}`(화면 표시용 — 판정에는 쓰지 않는다).
  - 알림: 판정 응답의 `lock_started:true`(잠금으로 바뀐 그 한 번)에서만 알림 서버로 이벤트를 보낸다. 이벤트 key 에 `locked_until` 을 넣어 재전송이 겹치지 않게 한다. 알림 전송 실패는 로그인 응답을 막지 않는다(앱 로그 1줄).
  - **관측 서버 장애의 뜻**: 연결 실패 · 5초 초과 · 2xx 가 아닌 응답 · 해석할 수 없는 본문. 같은 `attempt_id` 로 1회 재시도한 뒤에도 안 되면 그 로그인은 임시 제한으로 판정한다. 임시 제한의 횟수는 자리별 메모리이고 재시작·전환 때 0 이 된다(수용). 대기열 항목은 `attempt_id`·원래 시각을 갖고, 복귀 뒤 `replayed:true` 로 보낸다(현재 잠금 판정을 바꾸지 않는다). 장애 중 기록은 최선 노력이다 — 넘침·유실 건수를 앱 로그에 센다.
  - 속도 제한: 최근 60초 창, **자리별**(전환 중 두 자리가 함께 떠 있는 동안은 자리마다 10회 — 수용). 429 로 거절한 요청은 IP 마다 창당 첫 1건만 관측 서버에 기록한다(기록 폭주 방지), 나머지는 건수만 앱 로그에.
  - **앱 로그에는 IP · 입력 ID · 비밀번호를 적지 않는다** — 결과와 건수만(앱 로그는 Redis 스트림을 거쳐 로그 조회 화면에 나온다). IP 와 User-Agent 는 관측 서버의 시도 테이블에만 있다.
  - **IP 를 믿는 조건**: 집 쪽 포트는 인터넷에서 직접 닿을 수 있다(11-22 엣지 설정 확인 — 엣지 전용이 아니다). 어드민의 nginx 는 **엣지 IP 와 사설 대역에서 온 연결만** 받고 나머지는 닫는다. 엣지에서 온 연결이면 엣지가 넣은 `X-Real-IP` 를, 사설 대역에서 온 연결이면 실제 접속 주소를 앱에 넘긴다 — nginx 가 헤더를 다시 써서 앱은 한 헤더만 읽는다. 엣지 IP 는 저장소 밖 설정(`deploy/active/`)에 둔다.
  - **인증 경계의 구현 형태**: 공통 진입(middleware — 기본 거절, 허용 목록만 통과)에 더해, 다른 서버를 부르는 **모든 서버 쪽 함수와 Route Handler 가 같은 세션 검증 함수를 직접 호출**한다(둘 중 하나가 빠져도 막힌다). 로그인·로그아웃은 Route Handler 로 만든다(Server Action 을 쓰지 않는다 — 자리 사이의 액션 키·버전 문제를 피한다). 보호 화면과 데이터 경로는 요청마다 렌더링하고 `Cache-Control: no-store`. 비밀값을 읽는 모듈은 `server-only`. 다른 서버의 응답은 서버 쪽에서 화면에 필요한 칸만 골라 넘긴다.
  - `Origin` 검사: 헤더에서 추론하지 않고 설정값(`ADMIN_ORIGIN` = `https://admin.junproject.xyz`)과 글자까지 같은지 본다. 없거나 다르면 거절.
  - 세션: 두 자리는 같은 서명 키를 쓴다(같은 서버 `.env`). 서명과 발급 시각을 요청마다 검증한다. 쿠키 이름·경로는 발급과 삭제가 같다.
  - 상태 화면의 호출은 **병렬**, 각각 5초. 목록 화면의 기간·건수 상한은 어드민 서버 쪽에서도 강제한다.
  - 관측 서버 스키마 변경은 추가만(새 테이블·인덱스) — 구버전과 신버전 자리가 함께 떠 있어도 기존 조회·수집이 동작한다.
- **세부 2(11-22 리뷰 루프 1 반영 — 앞의 세부와 어긋나는 곳은 이쪽이 우선)**:
  - **재전송의 결과**: `POST /auth/attempts` 에 칸 `outcome`("success"|"failure"|"locked")을 더한다 — `replayed:true` 면 **필수**(없으면 422)이고 관측 서버는 그 값을 그대로 기록한다(어드민이 임시 제한으로 실제 내린 판정). `replayed:false` 면 받지 않는다(보내면 422). 배포 순서: 관측 서버 먼저.
  - **시간 초과는 재시도하지 않는다**(사용자 결정 11-22 "시간 초과는 재시도 없이"): 5초 안에 답이 없으면 바로 임시 제한으로 판정한다(로그인 최대 약 5초). 연결 실패 · 2xx 가 아닌 응답 · 해석할 수 없는 본문만 같은 `attempt_id` 로 1회 재시도. 시간 초과한 시도도 대기열에 넣어 복귀 뒤 같은 `attempt_id` 로 보낸다(관측 서버가 이미 기록했으면 처음 판정이 돌아온다).
  - **재전송 응답의 잠금 시작도 알린다**: 대기열 재전송의 응답이 `lock_started:true` 면 알림을 보낸다(응답을 잃었던 잠금 — key 에 `locked_until` 이 있어 겹치지 않는다).
  - 알림 전송은 로그인 응답을 **최대 2초**만 기다린다(그 안에 끝나지 않으면 응답을 먼저 보내고 실패를 로그 1줄).
  - **잠금을 건 그 시도의 응답**: 판정이 `lock_started:true` 면 관측 서버의 `outcome` 이 `"failure"` 여도 어드민은 "잠금"(HTTP 423, 잠금 문구)으로 답한다 — 임시 제한의 세 번째 실패와 같다. 관측 서버의 기록은 `failure` 그대로다(그 시도 자체는 실패였다).
  - **기록 범위**: 로그인 경로에 닿은 요청은 전부 기록한다 — 자격 검증에 이른 것은 `/auth/attempts`, 그 전에 거절한 것은 `/auth/attempts/rejected`(`reason` = `"rate_limited"` | `"origin_rejected"` | `"malformed"`). 거절 기록은 IP 마다 60초 창에 이유별 첫 1건만(폭주 방지), 나머지는 건수만 앱 로그에.
  - **속도 제한의 위치**: Origin 검사 → 속도 제한 → 본문 해석 순. 형식이 틀린 본문·상한을 넘는 입력도 속도 제한에 센다.
  - **해시 비용**: 설정된 비밀번호 해시의 argon2id 매개변수(m·t·p)가 더미 해시와 다르면 **설정 없음과 같이 로그인을 전부 거절**한다(시작 로그 1줄, 값은 찍지 않는다) — ID 틀림과 비밀번호 틀림의 시간이 갈리지 않게.
  - **종료 때의 대기열**: 종료 신호(SIGTERM)를 받으면 대기 중 건수와 누적 유실 건수를 앱 로그 1줄로 남긴다. 대기열에 넣을 때마다 현재 건수를 남긴다(강제 종료 때는 그 마지막 줄이 근사값이다 — 정확한 유실 건수는 보장하지 않는다. 수용).
  - **빌드 산출물의 값 검사**: 빌드 때는 비밀값이 없으므로 이름을 검사하고, **값 검사는 배포된 컨테이너 안에서** 실제 환경 변수 값으로 클라이언트 산출물을 검색한다(서버 검증 항목 — 값은 출력하지 않는다).
  - **인증 경계의 테스트**: middleware 를 직접 불러 `src/app` 에서 뽑은 보호 경로 전수(쿠키 없음 · 잘못된 서명 · 만료)를 고정하고, 보호 화면·Route Handler 가 세션 검증 함수를 부르는지도 고정한다 — 둘 중 하나를 빼면 테스트가 빨강이어야 한다.
  - 판정 시각은 어드민이 보낸 `at` 이다(호출자는 비밀값을 가진 어드민뿐이고 두 자리는 같은 서버의 시계).
  - **공개 전 차단 조건**: `.9` 에서 엣지를 거치지 않은 바깥 연결이 nginx 에 어떤 원본 주소로 보이는지 실측한다. 도커 브리지 주소로 보이면(사설로 통과) 공개하지 않고 nginx 의 네트워크 구성을 다시 설계한다.
  - 알려진 한계(수용): 관측 서버가 시도를 기록하고 응답만 잃은 경우, 어드민이 임시 제한으로 내린 판정과 관측 서버의 기록(처음 판정)이 다를 수 있다. 메모리 대기열이라 재전송 기회 전에 프로세스가 죽으면 그 기록과 알림은 가지 않는다.
  - 서버 검증 절차: `.9` 내부(http)에서는 `Secure` 쿠키·https Origin 비교 때문에 브라우저 로그인이 성립하지 않는다 — 내부에서는 curl 로 Origin·Cookie 를 직접 넣어 흐름을 확인하고, 브라우저의 "로그인 → 화면 → 로그아웃"은 공개 도메인(https)에서 확인한다(⑤ 의 서버 항목을 이렇게 읽는다).
- **세부 3(11-22 리뷰 루프 2 반영 — 앞의 세부들과 어긋나는 곳은 이쪽이 우선)**:
  - **로그인으로 보내는 주소**: 세션 없는 화면 요청의 이동 주소는 **요청의 Host 나 서버 자신의 호스트 이름에서 만들지 않는다** — 설정값 기준의 `<ADMIN_ORIGIN>/login` 을 낸다(공통 진입). nginx 는 앱이 낸 이동 주소를 경로만 남겨 바깥으로 `Location: /login` 을 낸다. 테스트는 공통 진입의 `Location` 이 글자 그대로 `<ADMIN_ORIGIN>/login` 임을 단언하고(요청 Host 를 바꿔도 같다), 바깥의 글자 `/login` 은 nginx 를 거친 실측으로 확인한다. (11-22 구현 중 정정 — 처음 문장은 "상대 주소 `/login` 을 그대로 낸다"였는데, Next 15.5 의 공통 진입은 상대 `Location` 을 받아들이지 못하고 500 을 낸다(실측 `ERR_INVALID_URL`). 뜻 — 내부 호스트 이름이 나가지 않는다 — 은 그대로다.)
  - **관측 판정의 전체 기한**: 첫 호출과 재시도를 합쳐 **5초 기한 하나**. 재시도는 남은 시간 안에서만 하고, 기한이 지나면 임시 제한으로 판정한다.
  - **거절 기록은 응답을 기다리게 하지 않는다**: 403·400·429 응답은 기록 전송을 기다리지 않는다. 전송은 뒤에서 끝까지 수행하고, 실패하면 대기열에 넣는다(시작만 하고 버리지 않는다).
  - **거절 기록의 창**: 네 이유 모두 IP 마다 고정 60초 창에 이유별 첫 1건(꾸준히 두드려도 1건).
  - **설정이 없으면 뜨지 않는다**(사용자 지적 11-22 "애초에 설정이 비어 있으면 구동을 못 하게 해야 되는 거 아니야?" — 앞의 "설정이 비면 로그인을 전부 거절"과 직전의 `not_configured` 결정을 대체한다): 서버가 뜰 때 로그인에 필요한 설정(계정 ID · 비밀번호 해시와 그 비용 · 세션 서명 키 · `ADMIN_ORIGIN` · 관측 서버 주소·비밀값)을 검사해, 빠졌거나 잘못됐으면 **0 이 아닌 코드로 끝낸다**. 로그에는 빠진 키 이름만 1줄(값은 찍지 않는다). 헬스 경로도 설정이 유효할 때만 정상(200)을 낸다 — 시작 검사가 건너뛰어져도 자리 헬스 확인에서 걸린다(배포가 실패로 끝나고 이전 자리가 계속 서비스한다). 빌드는 설정 없이 된다(검사는 서버가 실제로 뜰 때만). 거절 이유 `not_configured` 는 두지 않는다 — 관측 서버 계약의 `reason` 은 `rate_limited` | `origin_rejected` | `malformed` 그대로. 실행 중에 설정이 없는 상태에 닿는 코드 경로가 남아 있다면 거절(401)만 한다(기록 없음 — 정상 구동에서는 닿지 않는다).
  - **속도 제한 표가 가득 찼을 때**: 아직 창 안에 있는 IP 는 지우지 않는다. 표가 활성 항목으로 가득 차면 새 IP 는 거절(429)한다 — 닫힌 쪽. 이 포화 거절은 관측 서버에 기록하지 않고 건수만 앱 로그에(기록 폭주 방지).
  - **본문 읽기**: Origin 검사와 속도 제한을 본문을 읽기 **전에** 한다. 본문은 읽으면서 바이트 상한(4KB)과 시간 기한(3초)을 적용한다(다 읽은 뒤 재지 않는다). 상한·기한을 넘으면 `malformed`(400)로 처리하고 기록한다.
  - **임시 횟수의 초기화**: 관측 서버가 허용한 로그인 성공은 임시 제한의 메모리 횟수도 0 으로 만든다.
  - **대기열의 버릴 항목**: 재전송에 관측 서버가 **422**(본문 자체가 틀림 — 다시 보내도 같다)를 준 항목만 버리고, 버린 건수와 상태 코드를 앱 로그에 남긴다. 401·429·5xx·연결 실패·시간 초과는 남겨 다음에 다시 보낸다.
  - **관측 서버의 본문 오류**: 인증(`X-Observe-Secret`)을 본문 해석보다 먼저 판정한다. 해석할 수 없는 JSON 은 422 `invalid_request`(프레임워크의 400 이 아니다). `replayed:false` 에 `outcome` **칸이 있으면**(값이 null 이어도) 422.
  - **종료 로그의 위치**(사용자 결정 11-22 "컨테이너 로그로 충분"): 종료 때의 1줄은 컨테이너 로그(stdout)로 충족한다 — Redis 스트림으로의 전송은 시도하되 보장하지 않는다. 대기열에 넣을 때마다의 건수 로그는 평소처럼 스트림에도 간다.
- **세부 4(11-22 리뷰 루프 3 반영 — 앞의 세부들과 어긋나는 곳은 이쪽이 우선)**:
  - **설정의 형식도 검사한다**: "잘못됐으면"은 빈 값만이 아니다. `ADMIN_ORIGIN` 은 https 이고 출처 꼴 그대로여야 한다(`new URL(값).origin === 값` — 끝의 `/`·경로·scheme 없음은 잘못된 값). `OBSERVE_URL` 은 해석되는 http(s) 주소. 비밀번호 해시는 필수 비용 머리에 더해 **검증 라이브러리가 실제로 읽을 수 있어야** 한다(길이를 임의로 고정하지 않는다). `SESSION_SECRET` 은 32자 이상(기존). 형식이 틀리면 빈 값과 같이 종료(0 이 아닌 코드)·헬스 503. 공통 진입이 `ADMIN_ORIGIN` 을 해석하지 못할 때 요청 주소로 대신하는 경로는 두지 않는다.
  - **본문의 3초는 앱이 전체 기한으로 건다**: nginx 의 `client_body_timeout` 은 읽기 사이의 간격이라 전체 기한이 되지 못한다(11-22 리뷰어 실측 — 2초 간격으로 10초에 걸쳐 보낸 본문이 통과). 로그인 경로는 nginx 가 본문을 모으지 않고 흘려보내(`proxy_request_buffering off`) 앱의 4KB 상한과 **전체 3초 기한**이 실제로 걸리게 한다 — 넘으면 400 `malformed` 로 기록되고 속도 제한에도 든다. nginx 는 8KB 상한(413)과 읽기 간격만 맡는다. 느린 본문 하나가 앱의 연결을 붙잡는 시간은 최대 3초이고 그 앞에 Origin 검사와 속도 제한이 있다. (세부 3 에 메인이 수용으로 적었던 "nginx 가 먼저 끊는 요청은 기록 밖" 문장은 지운다 — nginx 가 8KB 초과로 413 을 낸 요청만 앱에 닿지 않는다.) nginx 를 거친 느린 본문(2초 간격)으로 3초 안팎에 끊기는지 실측한다.
  - **대기열은 스스로 다시 보낸다**: 대기열이 비어 있지 않은 동안 30초마다 재전송을 시도한다(관측 서버가 돌아오면 다음 로그인을 기다리지 않고 보낸다). 재전송은 한 번에 하나만 돈다(주기 실행과 로그인 뒤 실행이 겹치지 않는다). 도는 중에 들어온 항목도 다음 시도에서 빠지지 않는다. 주기 시도도 관측 호출의 5초 기한을 따르고, 실패한 항목은 남는다. 타이머는 프로세스 종료를 막지 않는다.
  - **기록하지 않은 거절의 건수 로그는 집계한다**: Origin 거절 · 표 포화 · 창 안의 반복 거절처럼 관측 서버에 보내지 않는 거절은 요청마다 로그를 남기지 않고, 이유별 60초에 1줄(그 창의 건수)로 남긴다. 창이 끝날 때와 종료 때 남은 건수를 빠뜨리지 않는다.
  - **"임시 제한 중"은 로그인 뒤에도 보인다**: 관측 서버에 닿지 않는 동안(마지막 관측 호출이 실패했거나 대기열에 항목이 있는 동안) 로그인 화면과 로그인 뒤의 화면(홈) 모두에 표시한다.
  - 관측 서버: `replayed` 칸이 있으면 Boolean 이어야 한다 — `null` 은 422(칸이 없을 때만 기본 false).
  - 옛 설명("빈 설정이면 앱은 뜨고 로그인은 전부 거절")이 남은 주석을 고친다.
- **세부 5(11-22 화면 task 의 판정)**:
  - **화면용 설정 키도 필수**(사용자 원칙 "설정이 비어 있으면 구동을 못 하게"의 적용 — 앞의 "ALERT_* 는 선택"을 대체한다): `DEPLOY_MASTER_URL`·`DEPLOY_SECRET`·`BACKEND_URL`·`ALERT_URL`·`ALERT_SECRET` 이 비었거나 주소 형식이 틀리면 뜨지 않는다(종료·헬스 503). 선택으로 남는 것은 로그 스트림 주소(`LOG_REDIS_URL`)뿐이다.

  - **장애 사유는 가려서 보여 준다**: 감시 대상의 DOWN 사유 · backend 의존성의 상세 · 관측 서버 헬스의 실패 종류는 주소 꼴(`scheme://host[:port]`, 맨 IPv4)을 `(주소)` 로 바꾸고 줄바꿈을 없앤 뒤 120자로 잘라 넘긴다. 다른 서버의 **오류 응답 본문** 원문은 여전히 넘기지 않는다.
  - 입력의 상한을 넘는 값은 줄여서 받지 않고 거절한다(다른 서버를 부르지 않는다). 다른 서버가 실패해도 화면·데이터 경로는 뜨고, 그 칸의 결과로 실패를 보인다.

### 10.1 비밀번호 보기 버튼 (task 04 안, stakes 낮음)
- 기본은 가림. 눈 버튼으로 보이기 ↔ 가리기. 버튼은 폼을 제출하지 않고, 상태를 저장하지 않는다.

### 10.2 배포 상세 (task 07 신설, stakes 중간 — 외부 API·시간 제한·캐시)
- **목표**: 배포 이력의 한 줄을 누르면 오른쪽에 상세가 열려 "이번 배포가 무엇을 바꾸는 배포인가"를 어드민 안에서 확인한다.
- **화면**: 넓은 화면은 왼쪽 목록 | 오른쪽 상세 분할. 좁은 화면은 상세가 화면 전체를 덮고 "목록으로" 버튼이 있다. 선택은 주소에 담는다(`/deploys?…&selected=<요청 ID>&commit=<SHA>`) — 새로 고침·뒤로 가기·주소 공유가 그대로 된다.
- **범위(A→B)**: B = 이 배포의 커밋. A = **같은 서비스에서 이 배포보다 앞서 성공한 가장 최근 배포의 커밋**. A 가 없으면(첫 배포·이력 밖) B 커밋 하나만 보여 준다. A 와 B 가 같으면 "변경 없음(같은 커밋 재배포)".
- **상세에 담는 것**: ① 배포 요약(서비스·상태·시각·실패 단계·걸린 시간) ② B 커밋에 연결된 PR 이 있으면 PR 번호·제목·본문·병합 시각 ③ A→B 커밋 목록(SHA 7자·제목·작성 시각) ④ 커밋 하나를 고르면 그 커밋의 바뀐 파일 목록과 파일별 diff(더한 줄·뺀 줄 색 + 기호).
- **데이터 출처**: GitHub REST API(서비스 저장소 6개 + admin — 전부 공개 저장소). 어드민 서버가 호출하고 브라우저는 GitHub 를 직접 부르지 않는다. 서비스 이름 → 저장소 이름은 코드에 고정한 표(허용 목록)로만 바꾼다 — 입력값으로 저장소를 고를 수 없다.
- **불변식**
  - 읽기 전용(GET 만). SHA 는 16진수 7~40자만, 요청 ID 는 기존 형식만 받는다 — 그 밖은 GitHub 를 부르지 않고 422 `invalid_input`(기존 화면 데이터 경로와 같은 꼴 — 처음 초안의 400 을 11-22 21:1x 에 바로잡음). 선택한 배포가 목록에 없으면 404.
  - 데이터 경로는 `service`(허용 목록)·`selected`(요청 ID)가 필수, `commit` 은 선택이며 A→B 목록에 든 SHA(40자, 완전 일치)만 받는다. A 는 그 서비스의 최근 200건 안에서 찾는다(밖이면 "A 없음"). A==B 면 커밋 목록은 비고 `commit` 은 받지 않는다. 커밋이 100개를 넘으면 B 에 가까운 100개를 남긴다.
  - PR 본문·커밋 메시지·diff 는 **글자 그대로** 보여 준다(HTML·마크다운으로 해석하지 않는다).
  - 호출마다 5초 제한, 재시도 없음. GitHub 가 실패해도 배포 요약과 목록은 그대로 보이고 상세 자리에 "GitHub: 닿지 않음 / 한도 초과" 같은 이유만 나온다.
  - 크기 상한: 커밋 목록 100개, 커밋 하나에 파일 100개, 파일 하나의 diff 500줄 — 넘으면 "더 있음 — GitHub 에서 보기" 링크. 조용히 자르지 않는다.
  - 캐시: SHA 로 정해지는 응답(커밋·비교)은 바뀌지 않으므로 메모리에 둔다(상한 있음, 재시작하면 비워짐). PR 조회는 10분.
  - `GITHUB_TOKEN` 은 **선택 설정**(없어도 뜬다). 없으면 GitHub 의 익명 한도(IP 당 시간당 60회), 있으면 5000회. 토큰은 서버 쪽에만 있고 권한은 공개 저장소 읽기뿐.
- **검증**: 가짜 GitHub 서버로 테스트(정상·PR 없음·A 없음·같은 커밋·한도 초과·시간 초과·상한 초과·잘못된 SHA) + 실제 GitHub 로 스모크 1회 + 사용자 화면 확인.
- **알려진 한계**: 강제 푸시로 A 가 B 의 조상이 아니면 GitHub 비교 결과를 그대로 보여 주고 "갈라진 이력" 표시. PR 없이 main 에 직접 푸시한 커밋은 PR 칸이 비어 있다.

### 10.3 데이터 출처 변경 — 커밋·diff 는 로컬 git 에서 (11-22 22:0x 사용자 제안·승인, task 05 에서 실행)

- **결정**: 커밋 목록과 커밋별 diff 는 **ci-cd agent 가 서버의 저장소에서 읽어** master 가 중계한다(별도 탐색 프로그램은 만들지 않는다). **PR 제목·본문만 GitHub** 에서 가져온다(상세 한 번에 1회 · 실패하면 PR 칸만 실패 표시). `GITHUB_TOKEN` 은 계속 선택.
- **시점**: 나머지 세 화면을 먼저 끝내고, task 05 의 ci-cd 변경(admin 등록)과 함께 넣는다. 그때까지 어드민은 지금의 GitHub 방식 그대로(미리보기용).
- **task 05 에서 정할 것(그때 세부 명세)**: agent 의 읽기 전용 조회 경로 둘(범위의 커밋 목록 · 커밋 하나의 diff)과 master 중계 계약 · SHA 형식 검사와 서비스 허용 목록(git 명령 인자 주입 차단) · 이력 깊이(`fetch --depth=50` — 범위가 로컬에 없을 때의 표시) · 배포 중인 작업 트리와 동시에 읽어도 되는지 · 크기 상한은 §10.2 와 같게 · ci-cd 는 배포 시스템이므로 stakes 높음.
- PR 본문이 길어 아래가 밀리는 것은 그대로 둔다(사용자: "스크롤이 필요하고 해도 된다").

## 12. task 05 세부 — 배포 상세의 커밋·diff 를 ci-cd agent 의 로컬 git 에서 (11-23 초안)

> 상태: **승인**(11-23 13:0x "진행하자" — 이력 깊이는 권장안: 이력 밖은 GitHub 링크로). §10.3 이 task 05 로 미룬 것의 세부다. stakes **높음**(ci-cd 는 서버에서 root 로 돌고 docker.sock 을 쥔다 · master 의 공개 계약에 경로가 늘어난다).

### 12.1 실코드에서 확인한 사실 (ci-cd 저장소, 11-23 탐색)
- agent 는 `POST /agent/ci` · `POST /agent/cd` 둘뿐이고 `X-Deploy-Secret`(상수 시간 비교)로 인증한다(`internal/agent/agent.go:94-151`, `internal/shared/auth.go:8-17`). master 는 `POST /deploy` · `GET /deploys` · `GET /deploys/{id}` · `GET /status`, 같은 비밀값(`internal/master/master.go:92-97`).
- master 컨테이너에는 저장소가 없다(agent 만 호스트의 clone 을 마운트 — `docker-compose.yml:30-34`). 그래서 git 은 agent 가 읽고 master 는 중계만 할 수 있다.
- git 실행은 인자 배열(`exec.CommandContext`, 셸 없음 — `internal/agent/pipeline.go:39-45`). SHA 검사는 `shared.ValidCommitSha` = `^[0-9a-f]{7,64}$`(`internal/shared/validate.go:6-8`). 서비스 이름은 맵 키 허용 목록.
- 배포 때 `git fetch --depth=50 origin main` → `reset --hard <sha>`(`pipeline.go:96-99`). 로컬 이력은 얕다.
- agent 에는 전역 잠금 하나(`busy`)가 있고 배포가 CI 10분·CD 4분까지 잡는다(`agent.go:35,128`).
- 테스트는 가짜 명령 실행기뿐이고 실제 git 저장소로 도는 테스트가 없다(`internal/agent/pipeline_test.go:30-53`).

### 12.2 계약
- **agent(새 경로 둘 — 읽기 전용, GET, `X-Deploy-Secret`)**
  - `GET /agent/git/commits?service=&from=<A>&to=<B>` → `{commits:[{sha, author_name, authored_at(ISO-8601 UTC), subject, body}], truncated(bool), range_complete(bool)}` — A 다음부터 B 까지(A 제외·B 포함), 최신순, 최대 100개(넘으면 B 에 가까운 100개 + `truncated:true`).
  - `GET /agent/git/commit?service=&sha=` → `{sha, author_name, authored_at, subject, body, files:[{path, previous_path|null, status("added"|"modified"|"deleted"|"renamed"), additions, deletions, binary(bool), patch(글자|null), patch_truncated(bool)}], files_truncated(bool)}` — 파일 100개, 파일 하나의 patch 500줄까지. 병합 커밋은 첫째 부모와의 차이.
  - 작성자 **이메일은 내지 않는다**(이름만).
  - 오류: 401 `unauthorized` · 422 `invalid_request`(서비스가 허용 목록 밖, SHA 꼴 아님, 칸 없음·중복) · 404 `commit_not_found`(그 SHA 가 로컬 저장소에 없음 — 얕은 이력 밖 포함) · 504 `git_timeout` · 500 `git_failed`(detail 은 내지 않는다 — 경로·환경이 샐 수 있다).
- **master(중계 — 새 경로 둘, GET, 같은 비밀값)**: `GET /deploys/git/commits?service=&from=&to=` · `GET /deploys/git/commit?service=&sha=`. master 도 같은 입력 검사를 먼저 하고(틀리면 agent 를 부르지 않는다), 그 서비스의 agent 를 불러 봉투를 그대로 돌려준다. agent 에 닿지 못하면 502 `agent_unreachable`.
- **어드민**: 배포 상세의 커밋 목록·diff 를 GitHub 대신 master 의 위 두 경로에서 읽는다. **PR 제목·본문만 GitHub** 에 남는다(`GITHUB_TOKEN` 은 계속 선택). 화면·주소·상한 표시는 §10.2 그대로. `commit_not_found` 는 "이 서버의 git 이력에 없음(최근 50개 밖일 수 있음) — GitHub 에서 보기" 로 보인다.

### 12.3 불변식
- **읽기만**: 새 경로는 저장소를 바꾸지 않는다 — `fetch` · `reset` · `checkout` · `gc` 를 부르지 않고, 네트워크에 나가지 않는다. 쓰는 git 명령은 `cat-file` · `log` · `show`(또는 `diff-tree`)뿐이고 `GIT_OPTIONAL_LOCKS=0` 으로 돈다.
- **인자 주입 차단**: 서비스는 허용 목록의 키로만 디렉터리를 고른다(입력 글자를 경로에 넣지 않는다). SHA 둘은 각각 `ValidCommitSha` 를 통과해야 하고, git 에는 인자 배열로, 옵션 끝 표시(`--end-of-options`) 뒤에 넘긴다. 범위 글자(`a..b`)를 입력으로 받지 않는다 — agent 가 검사한 두 SHA 로 만든다.
- **배포를 막지 않는다**: 조회는 `busy` 잠금을 잡지 않고, 배포 중에도 답한다. 조회 하나는 3초(agent) · 4초(master 중계)로 끊는다. 동시 조회 수에 상한(4)을 두고 넘으면 429.
- **크기 상한**: git 출력은 읽으면서 바이트 상한(2MB)을 걸고, 넘으면 자르되 `truncated` 로 알린다(조용히 자르지 않는다). 외부 diff 도구·textconv 를 쓰지 않는다(`--no-ext-diff --no-textconv`).
- **기존 경로 무변경**: `/agent/ci` · `/agent/cd` · `/deploy` · `/deploys` · `/status` 의 동작과 응답은 그대로(특성 테스트로 고정).
- 같은 task 에서 허용 목록에 `admin` 을 더한다(master · agent 두 곳).

### 12.5 load-bearing 가정 (착수 직후 스모크)
1. 얕은 저장소(`--depth=50`)에서 이력 안의 두 커밋 사이 `git log A..B` 와 `git show` 가 정상 동작하고, 이력 밖 SHA 는 `cat-file -e` 가 실패로 알려 준다.
2. 배포의 `fetch`/`reset --hard` 가 도는 동안의 `log`/`show` 가 저장소를 망가뜨리거나 배포를 실패시키지 않는다.

- **실증 결과(11-23, git 2.43 임시 저장소 — 원본 140커밋 · `--depth=50` clone)**: 가정 1 성립(이력 안 `log A..B` 10건 · `show` 정상, 이력 밖 SHA 는 `cat-file -e` 종료 128 · `log` 도 128). 가정 2 성립(`fetch --depth=50` + `reset --hard` 3바퀴와 동시에 `log`·`show` 400회 — 조회 실패 0, 배포 쪽 명령 전부 종료 0, `fsck` 0).
- **실증에서 나온 규칙 둘**:
  - **얕은 경계 커밋**: 이력의 가장 오래된 커밋은 부모가 로컬에 없어 `show` 가 파일 전체를 "추가"로 낸다(실측 — 31줄 추가로 표시). 틀린 diff 를 내지 않도록, 그 커밋(`shallow` 목록에 든 SHA)의 diff 요청은 404 `commit_not_found` 와 같은 갈래(`parent_unavailable`)로 답하고 어드민은 GitHub 링크로 넘긴다.
  - **git 메시지는 지역 설정을 탄다**(실측 — 한국어 오류 글자). 판정은 종료 코드로만 하고 `LC_ALL=C` 로 실행한다. 오류 글자를 파싱하지 않는다.

### 12.6 하지 않는 것
- 이력 깊이 늘리기(배포 경로의 `--depth` 변경) · 조회 때 필요한 만큼 fetch — 조회가 저장소를 바꾸게 된다. 이력 밖은 GitHub 링크로 넘긴다.
- 조회 전용 비밀값 분리 — 지금 master 의 조회도 `DEPLOY_SECRET` 하나를 쓴다. 분리는 ⑥(어드민에서 재배포)의 권한 설계 때.

### 12.7 설계 선검증 반영 (11-23 — codex 1회. 12.2~12.3 과 어긋나면 이 절이 우선)
- **실행 환경 고정**: git 자식 프로세스는 부모의 `GIT_*` 환경 변수를 물려받지 않는다(전부 뺀다). 넣는 것은 `LC_ALL=C` · `GIT_OPTIONAL_LOCKS=0` · `GIT_NO_LAZY_FETCH=1` · `GIT_NO_REPLACE_OBJECTS=1` · `GIT_TERMINAL_PROMPT=0` 과 `--no-pager`. 전역 설정(`safe.directory`)은 그대로 쓴다.
- **SHA 확정**: 정규식 통과 뒤 `rev-parse --verify --end-of-options <sha>^{commit}` 으로 **커밋인지 확인하고 40자 전체 SHA 로 확정**한 값만 뒤의 명령에 쓴다(약식 SHA 가 모호하거나 커밋이 아니면 404 `commit_not_found`). 판정은 종료 코드로만.
- **범위의 뜻**: 응답에 `relation` 을 둔다 — `"ancestor"`(A 가 B 의 조상 — 커밋 목록은 `A..B`) · `"not_ancestor"`(되돌린 배포 등 — 커밋 목록은 비고, 어드민은 "직전 배포가 이 커밋의 조상이 아님 — GitHub 에서 비교 보기"). `range_complete` 는 "목록에 얕은 경계 커밋이 들어 있지 않음"이다(들어 있으면 그 너머가 잘렸을 수 있어 false). 순서는 git 의 순회 순서(`--topo-order`)이고 B 쪽이 먼저다.
- **diff**: 병합 커밋은 `--diff-merges=first-parent`. 이름 바꾸기 탐지는 플래그로 고정(`-M`), 색 없음. **파일 경로는 `-z` 출력에서 읽는다**(patch 머리줄에서 파싱하지 않는다 — 탭·줄바꿈·따옴표가 든 경로).
- **크기 상한(레코드 단위로 자른다)**: git 명령 하나의 stdout 2MB — 넘으면 온전히 읽은 마지막 레코드(커밋·파일)까지만 쓰고 `truncated`/`files_truncated`. 칸별: 제목 500바이트 · 본문 8KB(넘으면 자르고 `body_truncated`) · patch 한 줄 2000바이트(넘는 줄은 잘라 표시) · patch 500줄. 최종 JSON 은 2MB 이하 — 넘으면 뒤 파일부터 patch 를 비우고 `patch_truncated`. stderr 는 응답에 넣지 않는다. **master 의 agent 응답 읽기 상한(지금 16KB — `master.go:295`)은 이 두 중계에 한해 4MB.**
- **동시성**: 동시 조회는 **2개**, 넘으면 기다리지 않고 즉시 429 `too_many_requests`. 기한(3초)이 지나면 git 자식 프로세스가 실제로 죽는지 테스트로 확인한다.
- **오류 사상(master 는 agent 의 상태·코드를 그대로 전달)**:

  | 상황 | agent | master 가 내는 것 |
  |---|---|---|
  | 비밀값 틀림 | 401 `unauthorized` | 401(자기 검사) |
  | 입력 틀림 | 422 `invalid_request` | 422(자기 검사 — agent 를 부르지 않음) |
  | 그 서비스의 agent 설정 없음 | — | 422 `invalid_request` |
  | SHA 가 로컬에 없음·커밋 아님·모호 | 404 `commit_not_found` | 404 그대로 |
  | 얕은 경계 커밋의 diff | 404 `parent_unavailable` | 404 그대로 |
  | 동시 조회 초과 | 429 `too_many_requests` | 429 그대로 |
  | git 기한 초과 | 504 `git_timeout` | 504 그대로 |
  | git 실패 | 500 `git_failed` | 500 그대로 |
  | agent 에 닿지 못함 / 4초 안에 답 없음 / 봉투 아님 | — | 502 `agent_unreachable` / 504 `agent_timeout` / 502 `unexpected_response` |

- **조회 범위**: 그 서비스의 로컬 저장소에 있는 커밋이면 배포 기록과 무관하게 조회된다(저장소가 공개라 수용).
- **라우터**: 새 `/deploys/git/...` 가 기존 `GET /deploys/{requestID}` · `GET /deploys` 와 섞이지 않음을 특성 테스트로 고정한다.
- **자원 경쟁(알려진 한계)**: 잠금을 잡지 않아도 diff 생성이 배포와 CPU·디스크를 나눠 쓴다. 동시 2개·3초·출력 상한으로 줄일 뿐 없애지 못한다 — 수용.

### 12.8 리뷰 루프 1 반영 (11-23 — 앞 절과 어긋나면 이 절이 우선)
- **범위의 세 번째 값 `relation:"unknown"`**: 배포 때마다 `fetch --depth=50` 을 하므로, 직전 배포 커밋 A 의 객체는 로컬에 남아 있는데 B 에서 A 까지의 이력이 얕은 경계에서 끊길 수 있다(실측 — 이 경우 `merge-base --is-ancestor` 가 "조상 아님"으로 답한다). 판정 순서:
  1. A 가 B 의 조상 → `"ancestor"`.
  2. 아니고, **B 의 조상 순회가 얕은 경계 커밋에 닿지 않는다**(이력이 온전하다) → `"not_ancestor"`.
  3. 아니고, B 가 A 의 조상 → `"not_ancestor"`(확실한 되돌림).
  4. 그 밖(순회가 얕은 경계에 닿았고 되돌림도 아님) → `"unknown"` — 200, 커밋 목록은 비고 `range_complete:false`. 어드민은 "이 서버의 git 이력으로는 알 수 없음(최근 50개 밖일 수 있음) — GitHub 에서 비교 보기".
- **형 바뀜(파일↔심볼릭 링크)**: git 은 patch 에서만 이를 두 조각으로 낸다. 한 파일(`status:"modified"`)로 내고 patch 는 두 조각을 이어 붙인다. **patch 조각과 파일의 짝이 맞지 않으면 순서로 밀어 맞추지 않는다** — 짝을 확정하지 못한 파일은 patch 를 비우고 `patch_truncated:true`.
- **파일 목록은 patch 와 따로 지킨다**: 파일 목록(경로·상태·줄 수)을 온전히 읽었으면 patch 출력이 상한에 걸려도 목록은 싣는다. patch 를 온전히 읽지 못한 파일만 patch 를 비우고 `patch_truncated:true`. `files_truncated` 는 파일 목록 자체가 잘렸을 때(100개 초과, 목록 출력 상한)만.
- **최종 JSON 2MB 는 두 응답 모두**: 커밋 목록은 봉투까지 포함한 크기를 재어 뒤(오래된) 커밋부터 빼고 `truncated:true`. 상세는 patch 를 다 비우고도 넘으면 뒤 파일부터 빼고 `files_truncated:true`.
- **오류 사상 표에 한 줄 추가(예외)**: agent 가 401 로 답하면(master 와 agent 의 비밀값 불일치 — 설정 실수) master 는 그대로 전달하지 않고 **502 `agent_unauthorized`** 를 낸다. 어드민의 비밀값이 틀린 것(401)과 구분하기 위해서다. 그 밖의 상태·코드는 그대로 전달.
- **쓰는 git 명령 목록(12.3 보완)**: `rev-parse` · `cat-file` · `log` · `show` · `diff-tree` · `merge-base` · `rev-list` — 전부 읽기 명령.
- **테스트**: 출력 상한(2MB)·레코드 단위 자르기를 500줄 상한과 겹치지 않는 사례로 고정한다. 테스트 대상 git 이 개발자의 전역 git 설정을 읽지 않게 한다(HOME 을 임시 디렉터리로).

### 12.9 리뷰 루프 2 반영 (11-23 — 앞 절과 어긋나면 이 절이 우선)
- **조회 하나는 변하지 않은 이력 위에서만 답한다(경쟁을 한 곳에서 닫는다)**: 얕은 경계 목록(`shallow` 파일의 내용)을 git 명령들 **앞과 뒤에** 읽어 비교한다. 같으면 그 결과를 낸다. 다르면(그 사이 배포의 fetch 가 이력을 바꿨다) 결과를 버리고 **한 번** 처음부터 다시 한다. 다시 해도 다르면 **503 `repository_changing`** 으로 답한다(어드민은 "배포가 이력을 바꾸는 중 — 잠시 뒤 새로 고침"). 두 경로 모두 같다. 이 규칙이 있으므로 경계 판정(얕은 경계 커밋의 `parent_unavailable`, `relation`, `range_complete`)은 그 한 번의 일관된 목록으로 한다 — 명령마다 따로 방어하지 않는다. 재시도를 포함해 기한(3초)은 조회 하나 전체에 걸린다. master 는 503 을 그대로 전달한다.
- **기한의 합**: agent 의 조회 기한(3초)과 자식 프로세스 정리 대기를 더한 값이 master 의 중계 기한(4초)보다 작아야 한다 — `git_timeout`(agent) 과 `agent_timeout`(master) 이 섞이지 않게. 기본값을 테스트로 고정한다.
- **master 의 성공 봉투 검사**: 200 이어도 `data` 가 그 경로의 필수 칸을 갖추지 않으면 502 `unexpected_response` — 커밋 목록은 `commits`(배열) · `relation`(글자) · `truncated` · `range_complete`(참거짓), 상세는 `sha`(글자) · `files`(배열) · `files_truncated`(참거짓).
- **최종 JSON 2MB 는 실제 직렬화 길이로 확인**한다(근사 계산만으로 끝내지 않는다).
- **서브모듈 표시 고정**: diff 에 `--submodule=short` — 설정(`diff.submodule=log`)에 따라 머리줄 없는 줄이 앞 파일의 patch 에 섞이지 않게.
- **알려진 한계**: UTF-8 이 아닌 바이트(옛 인코딩의 파일 내용·경로)는 JSON 으로 내면서 U+FFFD 로 바뀐다. 커밋 하나의 메시지가 2MB 를 넘으면 상세는 500 `git_failed`(후보).
- **테스트**: 상세의 "뒤 파일부터 patch 비우기"를 500줄 상한과 겹치지 않는 사례로 · 조회 도중 경계가 바뀌는 사례(git 감싸개가 경계 파일을 바꾼다 — 한 번 바뀌면 다시 해서 옳은 답, 계속 바뀌면 503) · patch 조각과 파일의 짝이 어긋나는 사례(감싸개가 조각을 빼거나 끼운다) · agent 의 422 를 master 가 그대로 전달.

### 12.10 리뷰 루프 3 반영 (11-23 — 사용자 결정 "A로 진행하자": 남은 3건을 고치고 그 부분만 재점검. 한도 3루프를 한 번 넘긴다)
- **작성자 이름 상한**: `author_name` 은 200바이트까지(글자 경계에서 자르고 끝에 `…`). 줄일 것을 다 줄이고도 최종 JSON 이 2MB 를 넘으면 그대로 내지 않고 500 `git_failed`.
- **테스트**: master 의 4MB 읽기 상한을 필수 칸을 갖춘 응답으로 고정(상한 바로 아래는 통째로 전달, 위는 502) · "재시도를 포함해 기한은 조회 하나 전체"를 재시도가 실제로 도는 사례로 고정 · 최종 JSON 의 실제 길이 확인을 고정.
- **알려진 한계(추가)**: 배포의 fetch 가 새 객체를 받았지만 경계 목록을 아직 확정하지 않은 짧은 틈에는 조회가 일시적으로 500 `git_failed` 일 수 있다(틀린 내용이 아니라 오류 — 새로 고침). 주석 태그의 SHA 는 그 태그가 가리키는 커밋으로 답한다(후보).

### 12.11 어드민 쪽 세부 (11-23 — task 05-b)
- **범위를 못 내도 배포하는 커밋 하나는 보인다**: `relation` 이 `not_ancestor`·`unknown` 이거나 범위 조회가 실패한 경우, 어드민은 커밋 B 하나를 따로 읽어 보인다(A 없음과 같은 꼴). 안내 문구와 GitHub 링크는 함께 나온다. B 도 읽지 못하면 그 실패를 보인다. B 밖의 `commit` 은 지금처럼 422. (근거: §10 의 요구 — "이번 배포가 어떤 배포인지 알 수 있게".)
- master 가 전체 커밋 수·전체 patch 줄 수를 주지 않으므로 "전체 N개 중" 표시는 "더 있음"으로 바뀐다. GitHub 비교의 "갈라진 이력" 표시는 "직전 배포가 이 커밋의 조상이 아님"으로 바뀐다.
- 커밋 순서는 화면의 기존 관례대로 오래된 것이 먼저. 범위 응답의 캐시는 `ancestor` 이고 온전하며 잘리지 않은 것만, 커밋 상세는 성공만.
