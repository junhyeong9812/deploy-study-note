### ⑩ Study 사이트 — 사용자 구상 (11-21, 순서 "그 순서대로 진행하자" 확인과 함께 받음)
착수 때 이 절을 인터뷰의 출발점으로 쓴다. 아래는 사용자가 말한 것을 옮긴 것이고, 설계 판단은 아직 없다.

- **목적**: 스터디 노트 사이트는 결국 사용자가 공부하기 위한 사이트다. 정리된 글을 읽고 → 퀴즈(문제)를 풀고 → Claude 모델과 대화하며 한 주제씩 공부해 나간다. 대상은 CS 지식·알고리즘·언어·오픈소스.
- **사용자 식별**: 접속하면 세션 토큰을 쿠키로 만든다. **비로그인이어도** 그 컴퓨터로 접속하면 토큰과 진행 상황을 기록해 공부를 이어갈 수 있다. 로그인하면 그 기록을 다른 PC 에서도 쓸 수 있다.
- **CS 화면(퀴즈형)**: 왼쪽 사이드바 / 가운데 주제 정리 글 / 오른쪽은 위아래로 나눠 위에 퀴즈(서술 답), 아래에 퀴즈에 대한 질문이나 LLM 에게 묻는 칸.
- **코딩 화면(myway 쪽 — 직접 코드를 치고 검증)**: 문제 / 코드 에디터(상단) + 로그 창·테스트 진행(하단) / LLM 질문. 디버깅도 할 수 있게. **LLM 은 정답을 알려 주지 않고 현재 코드를 바탕으로 놓친 부분을 짚어 준다.**
- **내용 구성**: CS 쪽은 순수 퀴즈형으로 두고, 코딩 테스트형은 별도 폴더에 미러링해 만든다(CS 지식과 myway 주제는 코딩 테스트 형태로 만들 수 있다). CS 에서 공부하며 퀴즈에 답해 문제와 친해진 뒤 해당 코딩 테스트를 보는 흐름. CS·오픈소스·히스토리는 **역사 순서를 따라 순차적으로** 학습할 수 있는 형태.
- **내용 정리**: 독후감·세미나 주제는 스터디 노트에서 제거한다. 그런 주제는 나중에 CS 의 각 섹션에 추가하는 형태로.
- **자료 갱신**: 자료의 메타데이터를 기준으로 하루 10개 정도씩 claude-code 로 "이 주제 정보가 최신인가"를 비교·분석해 갱신한다. 언어·히스토리도 주기적으로 갱신. CS 는 커리큘럼이 있으니 그 프로세스를 따라 만들어 간다.
- **나중(next)**: 백준 허브에서 문제를 더 가져오기.

- **사용자 보충(11-21)**:
  - "히스토리"는 스터디 노트 안에 있다 — 각 언어·프레임워크의 변천사처럼 버전별 내용을 정리한 것.
  - "myway"는 `project/myway` — 공부하려고 직접 풀어 나가는 문제들을 만들어 둔 곳. 그 주제로 CS 에 내용 정리는 해 두었고, 이를 코딩 테스트처럼 풀 수 있게 하고 싶다.
  - 비로그인 기록의 합치기: 세션 ID 를 DB 에 저장해 두고, 그 쿠키를 가진 브라우저에서 로그인하면 세션과 로그인 계정을 일치시켜 진행 상황을 계정에 동기화한 뒤 그 쿠키 세션은 삭제한다.
  - 퀴즈 답의 채점: 로컬 모델로 확인해도 되고, claude-code 의 sonnet 으로 확인하게 해도 된다.
  - 자료 갱신의 관리: 문서마다 메타데이터로 최신 업데이트 일자와 확인 일자를 남기고, 문서들의 상태를 메타데이터 DB 에 타임라인으로 저장해 순차적으로 처리한다. 세부는 착수 때 더 명확히 정한다.

착수 때 물어야 할 것(메인 메모 — 판단 아님): `project/myway` 와 스터디 노트 히스토리 폴더의 현재 구조(착수 때 조사) · 계정에 이미 진행 기록이 있을 때 세션 기록과 겹치는 주제를 어떻게 합칠지 · 코드 실행을 어디서 어떻게 격리해 돌릴지(언어·시간·자원 제한) · Claude 대화의 사용량 한도와 로컬 모델(.164)과의 분담(⑪과 겹침) · 비로그인 기록을 로그인 계정에 합치는 규칙(여러 기기의 기록이 충돌할 때) · 로그인 수단 · 퀴즈 답의 채점 방식(모델 채점인지 자기 채점인지) · 독후감·세미나 제거의 범위와 시점(study-note 저장소의 내용 변경 — 별도 작업) · 하루 10개 갱신을 어디서 돌리고 결과를 누가 검수하는지 · 한 번에 만들 범위(작업 분해).
